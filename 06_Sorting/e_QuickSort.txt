================================================================================
QUESTION: Quick Sort (Partitioning & Recursion)
FILE: e_QuickSort.java
================================================================================

1. WHAT IS THIS PROBLEM ABOUT?
--------------------------------------------------------------------------------
A fast in-place divide-and-conquer sorting algorithm. It picks a "pivot" element, partitions the array so all elements smaller than pivot are on left and larger on right, then recursively sorts both sides.

2. HOW TO THINK (INTUITION)?
--------------------------------------------------------------------------------
Pick one number to be the PIVOT (e.g. arr[low]).
Your goal is to put that pivot number in its EXACT final sorted position:
- Push all numbers smaller than or equal to pivot to its left.
- Push all numbers larger than pivot to its right.
Once the pivot is in its correct slot, it will NEVER move again!
Now just recursively sort the left side and right side.

3. STEP-BY-STEP APPROACH
--------------------------------------------------------------------------------
1. quickSort(arr, low, high):
   - if (low < high):
     - int pIndex = partition(arr, low, high);
     - quickSort(arr, low, pIndex - 1);
     - quickSort(arr, pIndex + 1, high);
2. partition(arr, low, high):
   - pivot = arr[low], i = low, j = high.
   - while (i < j):
     - while (arr[i] <= pivot && i <= high - 1) i++;
     - while (arr[j] > pivot && j >= low + 1) j--;
     - if (i < j) swap(arr[i], arr[j]);
   - swap(arr[low], arr[j]); // place pivot in final position
   - return j;

4. WHY THIS WORKS?
--------------------------------------------------------------------------------
After partitioning, arr[pIndex] is in its absolute sorted position, with smaller elements left and larger elements right. Recursively repeating on sub-arrays guarantees the whole array becomes sorted.

5. WHY NOT OTHER APPROACHES (WHY NOT THAT)?
--------------------------------------------------------------------------------
Why can Quick Sort be risky?
If the pivot is always the smallest or largest element (e.g. picking first element on already sorted array), partition splits array into 0 and N-1 elements. This degenerates into O(N^2) time!
Solution: Pick a random pivot or median-of-three to guarantee O(N log N) on average.

6. STEP-BY-STEP DRY RUN
--------------------------------------------------------------------------------
Input: [4, 6, 2, 5, 7, 9, 1, 3], low=0, high=7, pivot=4
i searches for element > 4 -> finds 6 at index 1
j searches for element <= 4 -> finds 3 at index 7
Swap 6 and 3 -> [4, 3, 2, 5, 7, 9, 1, 6]
i continues, finds 5 at index 3
j continues, finds 1 at index 6
Swap 5 and 1 -> [4, 3, 2, 1, 7, 9, 5, 6]
i and j cross!
Swap pivot 4 with arr[j]=1 -> [1, 3, 2, 4, 7, 9, 5, 6]
Pivot 4 is at index 3! All numbers to left [1, 3, 2] <= 4, all right [7, 9, 5, 6] > 4.

7. COMPLEXITY ANALYSIS
--------------------------------------------------------------------------------
- Time Complexity: Average: O(N log N), Worst: O(N^2)
  Reason: Average case divides in half each time (log N levels). Worst case splits 1 vs N-1.
- Space Complexity: O(log N) average, O(N) worst
  Reason: Recursion stack depth.

8. IMPORTANT TIPS, TRAPS & EDGE CASES
--------------------------------------------------------------------------------
- Quick Sort is IN-PLACE (does not need O(N) temp array like Merge Sort).
- Quick Sort is NOT stable by default because elements jump across the pivot during swaps.
