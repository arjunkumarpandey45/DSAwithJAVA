================================================================================
QUESTION: Sort 0s, 1s, and 2s / Sort Colors (Dutch National Flag Algorithm)
FILE: f_Sort0s1s2s.java
================================================================================

1. WHAT IS THIS PROBLEM ABOUT?
--------------------------------------------------------------------------------
Sort an array containing only 0s, 1s, and 2s in-place in a single pass without using any library sort.

2. HOW TO THINK (INTUITION)?
--------------------------------------------------------------------------------
Dutch National Flag (DNF) divides the array into 4 zones using 3 pointers (low, mid, high):
1. [0 ... low - 1] -> all 0s
2. [low ... mid - 1] -> all 1s
3. [mid ... high] -> unsorted zone (unknown)
4. [high + 1 ... n - 1] -> all 2s
Start with low = 0, mid = 0, high = n - 1.
Inspect arr[mid]:
- If 0: swap(low, mid), low++, mid++
- If 1: mid++ (it is already in the 1s zone)
- If 2: swap(mid, high), high-- (do NOT increment mid because the swapped element from high is unknown!)

3. STEP-BY-STEP APPROACH
--------------------------------------------------------------------------------
1. low = 0, mid = 0, high = n - 1.
2. While mid <= high:
   - If arr[mid] == 0: swap(arr[low], arr[mid]); low++; mid++;
   - Else if arr[mid] == 1: mid++;
   - Else (arr[mid] == 2): swap(arr[mid], arr[high]); high--;
3. Done.

4. WHY THIS WORKS?
--------------------------------------------------------------------------------
Every step shrinks the unknown zone [mid...high]. When mid > high, the unknown zone is empty, and all three segments (0s, 1s, 2s) are sorted.

5. WHY NOT OTHER APPROACHES (WHY NOT THAT)?
--------------------------------------------------------------------------------
Why not count frequencies (count 0s, 1s, 2s) and overwrite array?
Counting requires 2 passes (one to count, one to overwrite). DNF does it in exactly 1 pass and works even if elements are complex objects!

6. STEP-BY-STEP DRY RUN
--------------------------------------------------------------------------------
arr = [2, 0, 2, 1, 1, 0], low=0, mid=0, high=5
- mid=0 (2): swap mid and high -> [0, 0, 2, 1, 1, 2], high=4
- mid=0 (0): swap low and mid -> [0, 0, 2, 1, 1, 2], low=1, mid=1
- mid=1 (0): swap low and mid -> [0, 0, 2, 1, 1, 2], low=2, mid=2
- mid=2 (2): swap mid and high -> [0, 0, 1, 1, 2, 2], high=3
- mid=2 (1): mid=3
- mid=3 (1): mid=4 > high(3) -> STOP!
Result: [0, 0, 1, 1, 2, 2]

7. COMPLEXITY ANALYSIS
--------------------------------------------------------------------------------
- Time Complexity: O(N)
  Reason: At each step, either mid increases or high decreases. Exactly N steps.
- Space Complexity: O(1)
  Reason: In-place sorting with 3 pointers.

8. IMPORTANT TIPS, TRAPS & EDGE CASES
--------------------------------------------------------------------------------
- BIGGEST TRAP: When arr[mid] == 2, do NOT do mid++! The element brought from index high has not been examined yet, so mid must inspect it on the next iteration.
