================================================================================
QUESTION: Next Permutation (LeetCode 31)
FILE: j_NextPermutation.java
================================================================================

1. WHAT IS THIS PROBLEM ABOUT?
--------------------------------------------------------------------------------
Rearrange numbers into the lexicographically next greater permutation of numbers. If no such arrangement exists (array is sorted descending), rearrange to lowest possible order (sorted ascending).

2. HOW TO THINK (INTUITION)?
--------------------------------------------------------------------------------
Think about dictionary order (e.g. 1 2 5 4 3):
1. Scan from right to left to find the first dip: where arr[i] < arr[i + 1].
   Here: arr[1]=2 < arr[2]=5. Breakpoint index is 1 (value 2).
2. Scan from right to find the smallest number strictly greater than 2 to swap with.
   From right: 3 > 2! Swap 2 and 3 -> 1 3 5 4 2.
3. Reverse everything after index 1: reverse [5, 4, 2] -> [2, 4, 5].
Result: 1 3 2 4 5! This is the immediate next permutation!

3. STEP-BY-STEP APPROACH
--------------------------------------------------------------------------------
1. Find breakpoint: index i from n-2 down to 0 where arr[i] < arr[i + 1].
2. If no breakpoint found (i == -1), reverse entire array and return.
3. Find next greater: index j from n-1 down to i+1 where arr[j] > arr[i].
4. Swap arr[i] and arr[j].
5. Reverse array from index i + 1 to n - 1.

4. WHY THIS WORKS?
--------------------------------------------------------------------------------
The suffix after breakpoint was in strictly descending order. Swapping arr[i] with the next greater element in suffix makes the number slightly larger, and reversing the suffix turns it into ascending order (smallest possible suffix).

5. WHY NOT OTHER APPROACHES (WHY NOT THAT)?
--------------------------------------------------------------------------------
Why not generate all permutations, sort them, and pick the next one?
N! permutations for N = 15 is 1.3 trillion! That takes infinite time. This in-place scan takes O(N) time.

6. STEP-BY-STEP DRY RUN
--------------------------------------------------------------------------------
arr = [2, 1, 5, 4, 3, 0, 0]
Step 1: Scan right: 0<=0, 0<=3, 3<=4, 4<=5, 1<5! Breakpoint at index 1 (val 1).
Step 2: Scan right for > 1: find 3 at index 4.
Step 3: Swap 1 and 3 -> [2, 3, 5, 4, 1, 0, 0]
Step 4: Reverse from index 2..6: [5, 4, 1, 0, 0] -> [0, 0, 1, 4, 5]
Result: [2, 3, 0, 0, 1, 4, 5]

7. COMPLEXITY ANALYSIS
--------------------------------------------------------------------------------
- Time Complexity: O(N)
  Reason: At most 3 scans across the array (find breakpoint, find swap, reverse).
- Space Complexity: O(1)
  Reason: In-place modifications.

8. IMPORTANT TIPS, TRAPS & EDGE CASES
--------------------------------------------------------------------------------
- Check `arr[i] < arr[i + 1]`, NOT `<=`. Equal numbers do not create a strictly increasing order.
- If array is already [5, 4, 3, 2, 1], reverse(0, n-1) produces [1, 2, 3, 4, 5].
