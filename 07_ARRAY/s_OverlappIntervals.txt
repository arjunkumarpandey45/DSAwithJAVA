================================================================================
QUESTION: Merge Overlapping Intervals (LeetCode 56)
FILE: s_OverlappIntervals.java
================================================================================

1. WHAT IS THIS PROBLEM ABOUT?
--------------------------------------------------------------------------------
Given an array of intervals where intervals[i] = [start_i, end_i], merge all overlapping intervals.

2. HOW TO THINK (INTUITION)?
--------------------------------------------------------------------------------
First SORT all intervals by their start time!
Once sorted by start time, intervals that can overlap will sit right next to each other.
Iterate through the intervals:
- If current interval starts AFTER the previous interval ends: they do NOT overlap! Add it as a new interval.
- If current interval starts BEFORE or AT the previous interval end: they OVERLAP! Merge by updating: `prevEnd = Math.max(prevEnd, currEnd)`.

3. STEP-BY-STEP APPROACH
--------------------------------------------------------------------------------
1. Sort intervals by start time: Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0])).
2. List<int[]> merged = new ArrayList<>();
3. For each interval in intervals:
   - If merged is empty OR merged.getLast()[1] < interval[0]:
     - merged.add(interval);
   - Else:
     - merged.getLast()[1] = Math.max(merged.getLast()[1], interval[1]);
4. Return merged.toArray(new int[merged.size()][]).

4. WHY THIS WORKS?
--------------------------------------------------------------------------------
Sorting ensures start times are in chronological order. We only ever need to compare the current interval with the last interval added to the merged list.

5. WHY NOT OTHER APPROACHES (WHY NOT THAT)?
--------------------------------------------------------------------------------
Why not compare every interval with every other interval without sorting?
Without sorting, intervals can overlap in any arbitrary order, requiring an O(N^2) graph connected-components algorithm. Sorting simplifies it to an O(N log N) single pass.

6. STEP-BY-STEP DRY RUN
--------------------------------------------------------------------------------
intervals = [[1, 3], [2, 6], [8, 10], [15, 18]]
Sorted: same.
- interval [1, 3]: merged is empty -> add [1, 3]
- interval [2, 6]: 2 <= 3 (overlaps!) -> merge: max(3, 6) = 6 -> merged has [[1, 6]]
- interval [8, 10]: 8 > 6 (no overlap!) -> add [8, 10]
- interval [15, 18]: 15 > 10 (no overlap!) -> add [15, 18]
Result: [[1, 6], [8, 10], [15, 18]]

7. COMPLEXITY ANALYSIS
--------------------------------------------------------------------------------
- Time Complexity: O(N log N)
  Reason: Sorting takes O(N log N). The merging pass is O(N).
- Space Complexity: O(N)
  Reason: Space for storing the merged output intervals.

8. IMPORTANT TIPS, TRAPS & EDGE CASES
--------------------------------------------------------------------------------
- Remember `Math.max(last[1], interval[1])`: the current interval might be completely swallowed inside the previous one (e.g. [1, 5] and [2, 3]).
