================================================================================
QUESTION: Count Inversions in an Array
FILE: u_CountInversion.java
================================================================================

1. WHAT IS THIS PROBLEM ABOUT?
--------------------------------------------------------------------------------
An inversion is a pair of indices (i, j) such that i < j and arr[i] > arr[j].
Count the total number of inversions (measures how far the array is from being sorted).

2. HOW TO THINK (INTUITION)?
--------------------------------------------------------------------------------
Modified Merge Sort!
During the merge step of Merge Sort, we have two sorted halves: `left` and `right`.
If `arr[left] > arr[right]`, then because the left half is SORTED, arr[right] is smaller than arr[left] AND smaller than EVERY element after left in that half!
Number of inversions added = `(mid - left + 1)` in one single step!

3. STEP-BY-STEP APPROACH
--------------------------------------------------------------------------------
1. In mergeSort(arr, low, high):
   - count = 0;
   - if (low >= high) return 0;
   - mid = (low + high) / 2;
   - count += mergeSort(low, mid);
   - count += mergeSort(mid + 1, high);
   - count += merge(arr, low, mid, high);
   - return count;
2. In merge function:
   - while (left <= mid && right <= high):
     - if arr[left] <= arr[right]: add arr[left++] to temp;
     - else: count += (mid - left + 1); add arr[right++] to temp;

4. WHY THIS WORKS?
--------------------------------------------------------------------------------
Sorting elements locally does not change the inversion count between different partitions. By counting during merge, we count all cross-partition inversions efficiently in O(N log N).

5. WHY NOT OTHER APPROACHES (WHY NOT THAT)?
--------------------------------------------------------------------------------
Why not two nested loops?
Nested loops check every pair in O(N^2) time. For N = 100,000, N^2 = 10^10 (TLE). Merge sort counts in O(N log N).

6. STEP-BY-STEP DRY RUN
--------------------------------------------------------------------------------
Left = [2, 4], Right = [1, 3], mid = 1, left = 0
- Compare 2 and 1: 2 > 1 -> Inversions += (mid - left + 1) = (1 - 0 + 1) = 2 (pairs are (2, 1) and (4, 1))! Take 1.
- Compare 2 and 3: 2 <= 3 -> Take 2.
- Compare 4 and 3: 4 > 3 -> Inversions += (mid - left + 1) = (1 - 1 + 1) = 1 (pair (4, 3))! Take 3.
- Take 4.
Total inversions = 2 + 1 = 3.

7. COMPLEXITY ANALYSIS
--------------------------------------------------------------------------------
- Time Complexity: O(N log N)
  Reason: Same recurrence as Merge Sort: T(N) = 2T(N/2) + O(N).
- Space Complexity: O(N)
  Reason: Temporary array used during merge step.

8. IMPORTANT TIPS, TRAPS & EDGE CASES
--------------------------------------------------------------------------------
- In C++ and Java, total inversions can exceed 2 * 10^9. Always use `long` for the inversion counter in production/competitive programming.
