QUESTION: Find the Difference (LeetCode 389)
FILE: a_CheckDiff.java
================================================================================

1. WHAT IS THIS PROBLEM ABOUT?
--------------------------------------------------------------------------------
String 't' is generated by randomly shuffling string 's' and then adding one extra letter at a random position. Find the letter that was added.

2. HOW TO THINK (INTUITION)?
--------------------------------------------------------------------------------
Every character from string 's' is present in string 't', EXCEPT exactly one extra character.
Think:
Way 1 (Hash Map / Frequency Array): Count character occurrences in 's', subtract occurrences from 't'. Whichever count drops to -1 is the extra letter!
Way 2 (XOR - Genius Bit Trick): If you XOR a character with itself, it becomes 0 (x ^ x = 0).
If you XOR all characters of 's' and all characters of 't' together, every matching character cancels itself out to 0, leaving ONLY the extra character!

3. STEP-BY-STEP APPROACH
--------------------------------------------------------------------------------
HashMap approach:
1. Count character frequencies of 's': map.put(c, map.getOrDefault(c, 0) + 1).
2. For each character in 't': map.put(c, map.getOrDefault(c, 0) - 1).
3. Check map entries: whichever has value == -1 is the added character.

Bit Manipulation (XOR) approach:
1. char extra = 0;
2. For char c in s: extra ^= c;
3. For char c in t: extra ^= c;
4. return extra;

4. WHY THIS WORKS?
--------------------------------------------------------------------------------
By the properties of XOR:
1. a ^ a = 0 (identical characters cancel out).
2. a ^ 0 = a (identity).
3. XOR is commutative and associative (order does not matter).
The unique extra character remains at the end.

5. WHY NOT OTHER APPROACHES (WHY NOT THAT)?
--------------------------------------------------------------------------------
Why is XOR better than HashMap?
HashMap allocates objects, calculates hash codes, and takes O(N) extra space.
XOR uses O(1) space, requires no memory allocation, and runs in a single fast pass.

6. STEP-BY-STEP DRY RUN
--------------------------------------------------------------------------------
Input: s = "aea", t = "baea"
Map counting:
s has: 'a': 2, 'e': 1
Subtract t ("baea"):
- 'b': 0 - 1 = -1
- 'a': 2 - 1 = 1
- 'e': 1 - 1 = 0
- 'a': 1 - 1 = 0
Check: 'b' has value -1 -> return 'b'!

XOR trace:
extra = 0 ^ 'a' ^ 'e' ^ 'a' ^ 'b' ^ 'a' ^ 'e' ^ 'a'
= ('a' ^ 'a') ^ ('a' ^ 'a') ^ ('e' ^ 'e') ^ 'b'
= 0 ^ 0 ^ 0 ^ 'b' = 'b'!

7. COMPLEXITY ANALYSIS
--------------------------------------------------------------------------------
- Time Complexity: O(N)
  Reason: Scan both strings once.
- Space Complexity: O(1)
  Reason: Alphabet has at most 26 lowercase English letters.

8. IMPORTANT TIPS, TRAPS & EDGE CASES
--------------------------------------------------------------------------------
- Remember that characters in Java can be treated as integers (ASCII values), so arithmetic sum or XOR works directly on char!
