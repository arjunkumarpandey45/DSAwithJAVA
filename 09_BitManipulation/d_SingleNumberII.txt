================================================================================
QUESTION: Single Number II - Every Element Appears 3 Times Except One (LeetCode 137)
FILE: d_SingleNumberII.java
================================================================================

1. WHAT IS THIS PROBLEM ABOUT?
--------------------------------------------------------------------------------
Every integer appears three times except for one single integer which appears only once. Find that single one in linear time and O(1) space.

2. HOW TO THINK (INTUITION)?
--------------------------------------------------------------------------------
Approach 1 (Bit Sum Modulo 3):
For each bit position from 0 to 31, count how many numbers have a 1 at that bit.
If a number appears 3 times, its contribution to that bit sum is a multiple of 3 (0 or 3).
Therefore: if `(bitCount % 3) != 0`, that 1 MUST belong to the unique number!

Approach 2 (State Machine / Buckets - ones & twos):
Track bits seen 1 time (`ones`) and 2 times (`twos`):
`ones = (ones ^ num) & ~twos;`
`twos = (twos ^ num) & ~ones;`
When a bit appears a 3rd time, it automatically clears from both!

3. STEP-BY-STEP APPROACH
--------------------------------------------------------------------------------
Bit counting method:
1. int ans = 0;
2. For bit = 0 to 31:
   - int count = 0;
   - For num in arr: if ((num & (1 << bit)) != 0) count++;
   - if (count % 3 != 0) ans |= (1 << bit);
3. Return ans.

4. WHY THIS WORKS?
--------------------------------------------------------------------------------
Bits belonging to elements appearing 3 times always sum to multiples of 3. The modulo 3 remainder isolates the bits of the unique element.

5. WHY NOT OTHER APPROACHES (WHY NOT THAT)?
--------------------------------------------------------------------------------
Why not standard XOR?
Standard XOR cancels in pairs (x ^ x = 0). For 3 occurrences, x ^ x ^ x = x, so duplicates do NOT cancel out!

6. STEP-BY-STEP DRY RUN
--------------------------------------------------------------------------------
arr = [2, 2, 3, 2] -> in binary: 2 is 010, 3 is 011
- bit 0: numbers with bit 0 set: [3] -> count = 1. 1 % 3 = 1 -> ans has bit 0 set (1)
- bit 1: numbers with bit 1 set: [2, 2, 3, 2] -> count = 4. 4 % 3 = 1 -> ans has bit 1 set (2)
- bit 2: count = 0
ans = 011 in binary = 3!

7. COMPLEXITY ANALYSIS
--------------------------------------------------------------------------------
- Time Complexity: O(32 * N) = O(N)
  Reason: 32 passes over the array of size N.
- Space Complexity: O(1)
  Reason: Only primitive bit counter variables.

8. IMPORTANT TIPS, TRAPS & EDGE CASES
--------------------------------------------------------------------------------
- Works with negative numbers because 32-bit signed two's complement arithmetic behaves identically under bitwise extraction.
