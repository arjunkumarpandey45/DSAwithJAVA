================================================================================
QUESTION: Subarrays with K Different Integers (LeetCode 992)
FILE: h_SubArrByKdiffIntegers.java
================================================================================

1. WHAT IS THIS PROBLEM ABOUT?
--------------------------------------------------------------------------------
Given an array of integers nums and an integer k, return the number of good subarrays that contain exactly k different integers.

2. HOW TO THINK (INTUITION)?
--------------------------------------------------------------------------------
The same magical identity applies:
`Count(Exactly K Distinct) = Count(At Most K Distinct) - Count(At Most K - 1 Distinct)`!
Counting subarrays with AT MOST K distinct numbers is standard sliding window:
- Expand `right`, update map frequency.
- While `map.size() > k`: shrink `left`.
- Number of valid subarrays ending at `right` is `right - left + 1`!

3. STEP-BY-STEP APPROACH
--------------------------------------------------------------------------------
1. Helper atMost(nums, k):
   - Map<Integer, Integer> map = new HashMap<>();
   - int left = 0, right = 0, count = 0;
   - while (right < nums.length):
     - map.put(nums[right], map.getOrDefault(nums[right], 0) + 1);
     - while (map.size() > k):
       - map.put(nums[left], map.get(nums[left]) - 1);
       - if (map.get(nums[left]) == 0) map.remove(nums[left]);
       - left++;
     - count += (right - left + 1);
     - right++;
   - return count;
2. Main:
   - return atMost(nums, k) - atMost(nums, k - 1);

4. WHY THIS WORKS?
--------------------------------------------------------------------------------
Directly counting exactly K distinct integers with two pointers is ambiguous because shrinking left might leave K distinct or drop to K-1. Rephrasing into "at most" removes all ambiguity.

5. WHY NOT OTHER APPROACHES (WHY NOT THAT)?
--------------------------------------------------------------------------------
Why not check all subarrays with nested loops?
Nested loops take O(N^2). For N = 20,000, that is 4 * 10^8 operations (TLE). Sliding window solves it in O(N).

6. STEP-BY-STEP DRY RUN
--------------------------------------------------------------------------------
nums = [1, 2, 1, 2, 3], k = 2
atMost(2) = 12 subarrays with at most 2 distinct numbers.
atMost(1) = 5 subarrays with at most 1 distinct number.
Exactly 2 distinct = 12 - 5 = 7 subarrays!

7. COMPLEXITY ANALYSIS
--------------------------------------------------------------------------------
- Time Complexity: O(N)
  Reason: Both pointers traverse nums once in each of the two atMost calls.
- Space Complexity: O(K)
  Reason: HashMap stores at most K + 1 distinct keys.

8. IMPORTANT TIPS, TRAPS & EDGE CASES
--------------------------------------------------------------------------------
- In Java, you can replace HashMap with an integer frequency array `int[] freq = new int[nums.length + 1]` to make it 5x faster!
