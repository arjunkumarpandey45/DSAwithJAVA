================================================================================
QUESTION: Lower Bound and Upper Bound in Sorted Array
FILE: b_ImportantBSProblem.java
================================================================================

1. WHAT IS THIS PROBLEM ABOUT?
--------------------------------------------------------------------------------
1. Lower Bound: Smallest index where arr[index] >= target.
2. Upper Bound: Smallest index where arr[index] > target.

2. HOW TO THINK (INTUITION)?
--------------------------------------------------------------------------------
Lower Bound (arr[idx] >= target):
If arr[mid] >= target: mid COULD be our answer! Store `ans = mid`, and look LEFT (`high = mid - 1`) to see if an even smaller index qualifies.
If arr[mid] < target: mid is too small, must look RIGHT (`low = mid + 1`).

Upper Bound (arr[idx] > target):
Same logic, but condition is strictly `arr[mid] > target`.

3. STEP-BY-STEP APPROACH
--------------------------------------------------------------------------------
Lower Bound:
1. low = 0, high = n - 1, ans = n;
2. while (low <= high):
   - mid = low + (high - low) / 2;
   - if (arr[mid] >= target): ans = mid; high = mid - 1;
   - else: low = mid + 1;
3. return ans;

Upper Bound:
Same, but check `if (arr[mid] > target)`.

4. WHY THIS WORKS?
--------------------------------------------------------------------------------
Remembering `ans = mid` whenever the condition is met and continuing to search left guarantees we end up with the smallest valid index.

5. WHY NOT OTHER APPROACHES (WHY NOT THAT)?
--------------------------------------------------------------------------------
Why not linear search?
Binary search finds bounds in O(log N) rather than O(N).

6. STEP-BY-STEP DRY RUN
--------------------------------------------------------------------------------
arr = [2, 3, 6, 7, 8, 8, 11], target = 8
Lower Bound (>= 8):
- mid=3 (val 7) < 8 -> low = 4
- mid=5 (val 8) >= 8 -> ans = 5, high = 4
- mid=4 (val 8) >= 8 -> ans = 4, high = 3 < low -> stop!
Lower Bound is index 4!
Upper Bound (> 8):
- Index with first element > 8 is index 6 (val 11).

7. COMPLEXITY ANALYSIS
--------------------------------------------------------------------------------
- Time Complexity: O(log N)
  Reason: Binary search halving space each step.
- Space Complexity: O(1)
  Reason: Constant space.

8. IMPORTANT TIPS, TRAPS & EDGE CASES
--------------------------------------------------------------------------------
- Initialize `ans = n`. If no element in array satisfies the condition, the lower/upper bound is the imaginary index at the end of the array (n).
