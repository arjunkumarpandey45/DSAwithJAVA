================================================================================
QUESTION: Find First and Last Position of Element in Sorted Array (LeetCode 34)
FILE: c_FirstAndLastOccurance.java
================================================================================

1. WHAT IS THIS PROBLEM ABOUT?
--------------------------------------------------------------------------------
Given a sorted array of integers, find the starting and ending position of a given target value in O(log N) time. If target is not found, return [-1, -1].

2. HOW TO THINK (INTUITION)?
--------------------------------------------------------------------------------
To find FIRST occurrence:
When `arr[mid] == target`, don't stop! It might not be the first! Save `first = mid`, and keep searching LEFT: `high = mid - 1`!

To find LAST occurrence:
When `arr[mid] == target`, save `last = mid`, and keep searching RIGHT: `low = mid + 1`!

3. STEP-BY-STEP APPROACH
--------------------------------------------------------------------------------
1. Find first occurrence with binary search:
   - if arr[mid] == target: first = mid; high = mid - 1;
   - else if arr[mid] < target: low = mid + 1;
   - else: high = mid - 1;
2. If first == -1, target does not exist, return [-1, -1].
3. Find last occurrence with binary search:
   - if arr[mid] == target: last = mid; low = mid + 1;
   - else if arr[mid] < target: low = mid + 1;
   - else: high = mid - 1;
4. Return [first, last].

4. WHY THIS WORKS?
--------------------------------------------------------------------------------
Two independent binary searches isolate the leftmost and rightmost boundaries of the target range in O(log N) each.

5. WHY NOT OTHER APPROACHES (WHY NOT THAT)?
--------------------------------------------------------------------------------
Why not find any match and expand linearly left and right?
If the whole array is duplicates (e.g. 100,000 copies of target), expanding linearly takes O(N) time! Binary search guarantees O(log N).

6. STEP-BY-STEP DRY RUN
--------------------------------------------------------------------------------
arr = [5, 7, 7, 8, 8, 10], target = 8
Search First:
- mid=2 (7) < 8 -> low = 3
- mid=4 (8) == 8 -> first = 4, high = 3
- mid=3 (8) == 8 -> first = 3, high = 2 < low -> first = 3
Search Last:
- mid=4 (8) == 8 -> last = 4, low = 5
- mid=5 (10) > 8 -> high = 4 < low -> last = 4
Result: [3, 4]

7. COMPLEXITY ANALYSIS
--------------------------------------------------------------------------------
- Time Complexity: O(log N)
  Reason: Two separate binary searches: 2 * log2(N) = O(log N).
- Space Complexity: O(1)
  Reason: Constant space.

8. IMPORTANT TIPS, TRAPS & EDGE CASES
--------------------------------------------------------------------------------
- If `first == -1`, you can skip the second binary search entirely and return `[-1, -1]`.
