================================================================================
QUESTION: Single Element in a Sorted Array (LeetCode 540)
FILE: g_SingleElemennt.java
================================================================================

1. WHAT IS THIS PROBLEM ABOUT?
--------------------------------------------------------------------------------
You are given a sorted array consisting of only integers where every element appears exactly twice, except for one element which appears exactly once. Find this single element in O(log N) time and O(1) space.

2. HOW TO THINK (INTUITION)?
--------------------------------------------------------------------------------
Look at the index parity pattern before and after the single element:
Before single element (pairs are intact):
- 1st instance is at EVEN index
- 2nd instance is at ODD index (even, odd) (even, odd)...

After single element (everything is shifted by 1):
- 1st instance is at ODD index
- 2nd instance is at EVEN index (odd, even) (odd, even)...

At `mid`:
- If mid is odd, pair should match with `mid - 1`.
- If mid is even, pair should match with `mid + 1`.
If matching holds: we are on the LEFT of single element -> search RIGHT (`low = mid + 1`)!
If matching breaks: single element is at or to the LEFT of mid -> search LEFT (`high = mid`)!

3. STEP-BY-STEP APPROACH
--------------------------------------------------------------------------------
1. Handle edge cases: n == 1 return arr[0]; arr[0] != arr[1] return arr[0]; arr[n-1] != arr[n-2] return arr[n-1];
2. low = 1, high = n - 2;
3. while (low <= high):
   - mid = low + (high - low) / 2;
   - if (arr[mid] != arr[mid - 1] && arr[mid] != arr[mid + 1]) return arr[mid];
   - if ((mid % 2 == 1 && arr[mid] == arr[mid - 1]) || (mid % 2 == 0 && arr[mid] == arr[mid + 1])):
     - low = mid + 1; // left half is normal, search right
   - else: high = mid - 1; // anomaly is on left
4. Return -1.

4. WHY THIS WORKS?
--------------------------------------------------------------------------------
The single element disrupts the even-odd pairing order for all subsequent elements. Detecting whether pairing order is preserved locates which side the single element is on.

5. WHY NOT OTHER APPROACHES (WHY NOT THAT)?
--------------------------------------------------------------------------------
Why not XOR all elements?
XOR takes O(N) time. The problem requires O(log N) time.

6. STEP-BY-STEP DRY RUN
--------------------------------------------------------------------------------
arr = [1, 1, 2, 3, 3, 4, 4, 8, 8]
low = 1, high = 7, mid = 4 (val 3)
mid 4 is even. Check arr[4] == arr[5]? 3 == 4 is False! Pairing order broken on left!
high = mid - 1 = 3
low = 1, high = 3, mid = 2 (val 2)
Check neighbors of arr[2]: arr[1]=1 != 2 and arr[3]=3 != 2. Neither neighbor matches!
SINGLE ELEMENT FOUND: 2!

7. COMPLEXITY ANALYSIS
--------------------------------------------------------------------------------
- Time Complexity: O(log N)
  Reason: Binary search splits search space in half each step.
- Space Complexity: O(1)
  Reason: Only pointer variables.

8. IMPORTANT TIPS, TRAPS & EDGE CASES
--------------------------------------------------------------------------------
- Checking the first and last elements beforehand allows `low = 1` and `high = n - 2`, eliminating out-of-bounds checks for `mid - 1` and `mid + 1`!
