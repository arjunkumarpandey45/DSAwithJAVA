================================================================================
QUESTION: Koko Eating Bananas (LeetCode 875)
FILE: j_KokoEatingBananas.java
================================================================================

1. WHAT IS THIS PROBLEM ABOUT?
--------------------------------------------------------------------------------
Koko loves bananas. There are n piles. The guards return in h hours. Find the minimum integer eating speed k (bananas/hour) such that Koko can eat all bananas within h hours.

2. HOW TO THINK (INTUITION)?
--------------------------------------------------------------------------------
This is the classic "Binary Search on Answer" problem!
What is the minimum possible speed? 1 banana/hour.
What is the maximum speed Koko could ever need? `max(piles)` (eating the biggest pile in 1 hour).
If speed `k` is enough to finish in <= h hours:
Can Koko do it even SLOWER? Save `ans = k`, search LEFT: `high = mid - 1`!
If speed `k` is too slow (hours > h): Koko MUST eat faster, search RIGHT: `low = mid + 1`!

3. STEP-BY-STEP APPROACH
--------------------------------------------------------------------------------
1. Find max element in piles -> high = max(piles), low = 1, ans = high.
2. while (low <= high):
   - int mid = low + (high - low) / 2;
   - long hours = calculateHours(piles, mid);
   - if (hours <= h): ans = mid; high = mid - 1;
   - else: low = mid + 1;
3. calculateHours(piles, speed):
   - long total = 0;
   - for pile in piles: total += (pile + speed - 1) / speed; // ceil division
   - return total;

4. WHY THIS WORKS?
--------------------------------------------------------------------------------
Total hours required is a monotonically decreasing function of eating speed. Monotonicity guarantees binary search correctness.

5. WHY NOT OTHER APPROACHES (WHY NOT THAT)?
--------------------------------------------------------------------------------
Why not test speed 1, 2, 3... linearly?
If max pile is 10^9, testing speeds linearly takes 10^9 * N operations (TLE). Binary search tests only log(10^9) = 30 speeds!

6. STEP-BY-STEP DRY RUN
--------------------------------------------------------------------------------
piles = [3, 6, 7, 11], h = 8
low = 1, high = 11
- mid = 6: hours = ceil(3/6)+ceil(6/6)+ceil(7/6)+ceil(11/6) = 1+1+2+2 = 6 <= 8! ans=6, high=5
- mid = 3: hours = 1+2+3+4 = 10 > 8! low = 4
- mid = 4: hours = 1+2+2+3 = 8 <= 8! ans=4, high=3 < low -> STOP!
Minimum speed = 4 bananas/hour.

7. COMPLEXITY ANALYSIS
--------------------------------------------------------------------------------
- Time Complexity: O(N * log(max(piles)))
  Reason: Binary search runs log(max(piles)) times, each step calculates hours across N piles.
- Space Complexity: O(1)
  Reason: Constant space.

8. IMPORTANT TIPS, TRAPS & EDGE CASES
--------------------------------------------------------------------------------
- Fast ceil division without Math.ceil: `(pile + speed - 1) / speed`.
- Use `long` for total hours to prevent integer overflow.
