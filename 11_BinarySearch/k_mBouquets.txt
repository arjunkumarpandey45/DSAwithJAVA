================================================================================
QUESTION: Minimum Number of Days to Make m Bouquets (LeetCode 1482)
FILE: k_mBouquets.java
================================================================================

1. WHAT IS THIS PROBLEM ABOUT?
--------------------------------------------------------------------------------
You have bloomDay array where bloomDay[i] is the day the i-th flower blooms. You need to make m bouquets, each bouquet using k adjacent flowers. Return the minimum days to make m bouquets, or -1 if impossible.

2. HOW TO THINK (INTUITION)?
--------------------------------------------------------------------------------
Binary Search on Answer!
First check: Do we even have enough flowers? If `(long) m * k > bloomDay.length`, it is impossible! Return -1.
Search space for days:
- Minimum days = min(bloomDay)
- Maximum days = max(bloomDay)
At day `mid`: Count how many bouquets of k adjacent bloomed flowers can be made.
- If count >= m: possible! Save `ans = mid`, try fewer days (`high = mid - 1`).
- Else: not enough bouquets, need more days (`low = mid + 1`).

3. STEP-BY-STEP APPROACH
--------------------------------------------------------------------------------
1. If ((long)m * k > bloomDay.length) return -1;
2. low = min(bloomDay), high = max(bloomDay), ans = high;
3. while (low <= high):
   - mid = low + (high - low) / 2;
   - if (isPossible(bloomDay, mid, m, k)): ans = mid; high = mid - 1;
   - else: low = mid + 1;
4. isPossible helper:
   - bouquets = 0, count = 0;
   - for day in bloomDay:
     - if (day <= mid): count++; if (count == k) { bouquets++; count = 0; }
     - else: count = 0; // broke adjacency!
   - return bouquets >= m;

4. WHY THIS WORKS?
--------------------------------------------------------------------------------
More days mean more flowers bloom. The number of bouquets is non-decreasing with respect to time, allowing binary search.

5. WHY NOT OTHER APPROACHES (WHY NOT THAT)?
--------------------------------------------------------------------------------
Why not check day by day?
Max day can be 10^9. Linear checking takes 10^9 * N (TLE).

6. STEP-BY-STEP DRY RUN
--------------------------------------------------------------------------------
bloomDay = [1, 10, 3, 10, 2], m = 3, k = 1
Each bouquet needs 1 flower. We need 3 flowers.
low = 1, high = 10
- mid = 5: bloomed on day 5: flower 0(1), 2(3), 4(2) -> 3 flowers bloomed >= 3! ans=5, high=4
- mid = 2: bloomed on day 2: flower 0(1), 4(2) -> 2 flowers < 3 -> low=3
- mid = 3: bloomed on day 3: flower 0(1), 2(3), 4(2) -> 3 flowers! ans=3, high=2 < low -> STOP!
Answer: 3 days.

7. COMPLEXITY ANALYSIS
--------------------------------------------------------------------------------
- Time Complexity: O(N * log(max - min))
  Reason: Binary search over day range, O(N) check per step.
- Space Complexity: O(1)
  Reason: Constant space.

8. IMPORTANT TIPS, TRAPS & EDGE CASES
--------------------------------------------------------------------------------
- CRITICAL: `(long) m * k` must be cast to `long` before multiplication, because `m * k` can be 10^5 * 10^5 = 10^10 (overflows int).
