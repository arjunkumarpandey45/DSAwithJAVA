================================================================================
QUESTION: Median of Two Sorted Arrays (LeetCode 4)
FILE: q_MedianOfSortedArray.java
================================================================================

1. WHAT IS THIS PROBLEM ABOUT?
--------------------------------------------------------------------------------
Given two sorted arrays nums1 and nums2 of size m and n respectively, return the median of the two sorted arrays in O(log(min(m, n))) time.

2. HOW TO THINK (INTUITION)?
--------------------------------------------------------------------------------
The Masterpiece of Binary Search:
Median splits the combined sorted array of size (m + n) into two equal halves (left half and right half).
Left half must contain `k = (m + n + 1) / 2` elements total.
Binary search on how many elements to take from nums1 into the left half (`cut1`):
- If we take `cut1` elements from nums1, we MUST take `cut2 = k - cut1` elements from nums2!
Four boundary values around the cut:
- l1 = nums1[cut1 - 1], r1 = nums1[cut1]
- l2 = nums2[cut2 - 1], r2 = nums2[cut2]
A valid partition occurs when `l1 <= r2` AND `l2 <= r1`!
- If l1 > r2: took too many from nums1, move cut left: `high = cut1 - 1`.
- If l2 > r1: took too few from nums1, move cut right: `low = cut1 + 1`.

3. STEP-BY-STEP APPROACH
--------------------------------------------------------------------------------
1. Ensure nums1 is the smaller array: if (m > n) return findMedian(nums2, nums1);
2. low = 0, high = m, totalLeft = (m + n + 1) / 2;
3. while (low <= high):
   - int cut1 = (low + high) / 2;
   - int cut2 = totalLeft - cut1;
   - int l1 = (cut1 == 0) ? Integer.MIN_VALUE : nums1[cut1 - 1];
   - int l2 = (cut2 == 0) ? Integer.MIN_VALUE : nums2[cut2 - 1];
   - int r1 = (cut1 == m) ? Integer.MAX_VALUE : nums1[cut1];
   - int r2 = (cut2 == n) ? Integer.MAX_VALUE : nums2[cut2];
   - if (l1 <= r2 && l2 <= r1):
     - if ((m + n) % 2 == 1) return Math.max(l1, l2);
     - else return (Math.max(l1, l2) + Math.min(r1, r2)) / 2.0;
   - else if (l1 > r2) high = cut1 - 1;
   - else low = cut1 + 1;

4. WHY THIS WORKS?
--------------------------------------------------------------------------------
Once `l1 <= r2` and `l2 <= r1`, all elements in the left partition are <= all elements in the right partition. Max(l1, l2) is the exact median element.

5. WHY NOT OTHER APPROACHES (WHY NOT THAT)?
--------------------------------------------------------------------------------
Why not merge both arrays?
Merging takes O(m + n) time and O(m + n) space. Partition binary search takes O(log(min(m, n))) time and O(1) space.

6. STEP-BY-STEP DRY RUN
--------------------------------------------------------------------------------
nums1 = [1, 3], nums2 = [2]
m = 2, n = 1 -> swap: nums1 = [2] (m=1), nums2 = [1, 3] (n=2)
totalLeft = (1 + 2 + 1) / 2 = 2
low = 0, high = 1 -> cut1 = 0, cut2 = 2
l1 = -INF, r1 = 2
l2 = nums2[1] = 3, r2 = INF
l2(3) > r1(2) -> low = cut1 + 1 = 1
cut1 = 1, cut2 = 1:
l1 = nums1[0]=2, r1 = INF
l2 = nums2[0]=1, r2 = nums2[1]=3
Check: l1(2) <= r2(3) and l2(1) <= r1(INF) -> VALID!
Odd length: max(l1, l2) = max(2, 1) = 2.0!

7. COMPLEXITY ANALYSIS
--------------------------------------------------------------------------------
- Time Complexity: O(log(min(M, N)))
  Reason: Binary search only operates on the smaller array.
- Space Complexity: O(1)
  Reason: Only boundary variables.

8. IMPORTANT TIPS, TRAPS & EDGE CASES
--------------------------------------------------------------------------------
- Always ensure `nums1.length <= nums2.length` at the start to avoid index out of bounds on `cut2`!
