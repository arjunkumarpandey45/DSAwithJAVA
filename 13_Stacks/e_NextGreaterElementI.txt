================================================================================
QUESTION: Next Greater Element I (LeetCode 496)
FILE: e_NextGreaterElementI.java
================================================================================

1. WHAT IS THIS PROBLEM ABOUT?
--------------------------------------------------------------------------------
The next greater element of an element x is the first greater element to its right in the array.
Given nums1 (subset of nums2), find the next greater element for each element in nums1 using nums2.

2. HOW TO THINK (INTUITION)?
--------------------------------------------------------------------------------
Monotonic Decreasing Stack:
Scan `nums2` from right to left.
Maintain a stack of candidate next greater elements:
- Any element on the stack that is <= current element can NEVER be the next greater element for current OR anything to current's left! Pop them!
- After popping, the top of the stack is the Next Greater Element! If stack is empty, it is -1.
- Push current element to stack.
Store results in a HashMap: `map.put(nums2[i], nextGreater)`. Then look up answers for nums1.

3. STEP-BY-STEP APPROACH
--------------------------------------------------------------------------------
1. Map<Integer, Integer> map = new HashMap<>();
2. Stack<Integer> st = new Stack<>();
3. For i = nums2.length - 1 down to 0:
   - while (!st.isEmpty() && st.peek() <= nums2[i]) st.pop();
   - int nextGreater = st.isEmpty() ? -1 : st.peek();
   - map.put(nums2[i], nextGreater);
   - st.push(nums2[i]);
4. Build answer for nums1: ans[i] = map.get(nums1[i]).

4. WHY THIS WORKS?
--------------------------------------------------------------------------------
Smaller elements to the right are shadowed by larger elements to their left. Maintaining a strictly decreasing stack from right-to-left ensures the next greater element is always at the top.

5. WHY NOT OTHER APPROACHES (WHY NOT THAT)?
--------------------------------------------------------------------------------
Why not nested loops searching right in nums2?
Nested loops take O(N * M) time. Monotonic stack solves it in O(N + M) linear time.

6. STEP-BY-STEP DRY RUN
--------------------------------------------------------------------------------
nums2 = [1, 3, 4, 2], scan from right:
- 2: stack empty -> NGE=-1, push 2. st=[2]
- 4: 2 <= 4 -> pop 2. stack empty -> NGE=-1, push 4. st=[4]
- 3: 4 > 3 -> NGE=4! push 3. st=[4, 3]
- 1: 3 > 1 -> NGE=3! push 1. st=[4, 3, 1]
nums1 = [4, 1, 2] -> map lookups: 4 -> -1, 1 -> 3, 2 -> -1 -> [-1, 3, -1]

7. COMPLEXITY ANALYSIS
--------------------------------------------------------------------------------
- Time Complexity: O(N + M)
  Reason: Each element in nums2 is pushed and popped at most once.
- Space Complexity: O(M)
  Reason: Stack and HashMap store elements of nums2.

8. IMPORTANT TIPS, TRAPS & EDGE CASES
--------------------------------------------------------------------------------
- Condition is `st.peek() <= arr[i]`: we want strictly greater, so equal elements must be popped.
