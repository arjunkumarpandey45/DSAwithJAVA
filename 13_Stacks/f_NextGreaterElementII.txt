================================================================================
QUESTION: Next Greater Element II - Circular Array (LeetCode 503)
FILE: f_NextGreaterElementII.java
================================================================================

1. WHAT IS THIS PROBLEM ABOUT?
--------------------------------------------------------------------------------
Find the next greater element for every element in a CIRCULAR array (the next element of the last element is the first element of the array).

2. HOW TO THINK (INTUITION)?
--------------------------------------------------------------------------------
How to simulate a circular array without actually copying the array?
Hypothetically double the array length to 2N!
Loop from index `2N - 1` down to 0.
Use modulo indexing: `arr[i % n]`!
During the first pass (2N - 1 down to N), we populate the stack with future circular candidates.
During the second pass (N - 1 down to 0), we record the actual answers into `nge[i]`!

3. STEP-BY-STEP APPROACH
--------------------------------------------------------------------------------
1. int[] nge = new int[n]; Stack<Integer> st = new Stack<>();
2. For i = 2 * n - 1 down to 0:
   - while (!st.isEmpty() && st.peek() <= arr[i % n]) st.pop();
   - if (i < n): nge[i] = st.isEmpty() ? -1 : st.peek();
   - st.push(arr[i % n]);
3. Return nge.

4. WHY THIS WORKS?
--------------------------------------------------------------------------------
Simulating a 2N traversal ensures that every element has the chance to look ahead past the end of the array back to index 0.

5. WHY NOT OTHER APPROACHES (WHY NOT THAT)?
--------------------------------------------------------------------------------
Why not physically create an array of size 2N?
Creating an array of size 2N takes double the heap memory. `i % n` simulates circularity with zero extra array allocation.

6. STEP-BY-STEP DRY RUN
--------------------------------------------------------------------------------
arr = [1, 2, 1], n = 3, loop from i = 5 down to 0:
i = 5..3: fills stack with [2, 1]
i = 2 (arr[2]=1): stack top is 2 > 1 -> nge[2] = 2
i = 1 (arr[1]=2): 2 <= 2 (pop), stack top is -1 -> nge[1] = -1
i = 0 (arr[0]=1): stack has [2], 2 > 1 -> nge[0] = 2
Result: [2, -1, 2]

7. COMPLEXITY ANALYSIS
--------------------------------------------------------------------------------
- Time Complexity: O(N)
  Reason: Loop runs 2N times. Each element pushed and popped at most twice.
- Space Complexity: O(N)
  Reason: Stack of size up to N.

8. IMPORTANT TIPS, TRAPS & EDGE CASES
--------------------------------------------------------------------------------
- Only record answers when `i < n`! For `i >= n`, we are merely pre-warming the stack.
