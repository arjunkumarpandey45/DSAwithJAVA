================================================================================
QUESTION: Sliding Window Maximum (LeetCode 239)
FILE: s_maxSlidingWindow.java
================================================================================

1. WHAT IS THIS PROBLEM ABOUT?
--------------------------------------------------------------------------------
You are given an array of integers nums, and a sliding window of size k moving from left to right. Return the max element in each sliding window.

2. HOW TO THINK (INTUITION)?
--------------------------------------------------------------------------------
Monotonic Decreasing Deque (Double Ended Queue):
Store INDICES in the deque such that values are strictly DECREASING:
At each step `i`:
1. Remove out-of-bounds indices from the front: `q.peek() <= i - k`.
2. Maintain decreasing order: while `!q.isEmpty() && nums[q.peekLast()] <= nums[i]`, remove from back (they can never be the max because `nums[i]` is newer AND larger!).
3. Add `i` to back of deque.
4. The maximum element in the window is ALWAYS at `q.peekFirst()`!

3. STEP-BY-STEP APPROACH
--------------------------------------------------------------------------------
1. Deque<Integer> q = new ArrayDeque<>();
2. int[] ans = new int[n - k + 1];
3. For i = 0 to n - 1:
   - if (!q.isEmpty() && q.peekFirst() <= i - k) q.pollFirst(); // out of window
   - while (!q.isEmpty() && nums[q.peekLast()] <= nums[i]) q.pollLast(); // smaller elements useless
   - q.offerLast(i);
   - if (i >= k - 1) ans[i - k + 1] = nums[q.peekFirst()];
4. Return ans.

4. WHY THIS WORKS?
--------------------------------------------------------------------------------
The front of the deque always holds the index of the maximum element in the current window. Elements that are older and smaller are discarded immediately.

5. WHY NOT OTHER APPROACHES (WHY NOT THAT)?
--------------------------------------------------------------------------------
Why not PriorityQueue (Max-Heap)?
Heap takes O(N log k) time and removing out-of-window elements takes O(k). Monotonic deque takes O(N) linear time!

6. STEP-BY-STEP DRY RUN
--------------------------------------------------------------------------------
nums = [1, 3, -1, -3, 5, 3, 6, 7], k = 3
i=0 (1): q=[0]
i=1 (3): 1 <= 3 -> pop 0, q=[1(val 3)]
i=2 (-1): -1 < 3 -> q=[1(3), 2(-1)] -> window 0 complete: ans[0] = nums[1] = 3
i=3 (-3): q=[1(3), 2(-1), 3(-3)] -> ans[1] = 3
i=4 (5): 1 <= 4-3 (remove 1), pop -3, pop -1 -> q=[4(5)] -> ans[2] = 5
i=5 (3): q=[4(5), 5(3)] -> ans[3] = 5
i=6 (6): pop 3, pop 5 -> q=[6(6)] -> ans[4] = 6
i=7 (7): pop 6 -> q=[7(7)] -> ans[5] = 7
Result: [3, 3, 5, 5, 6, 7]

7. COMPLEXITY ANALYSIS
--------------------------------------------------------------------------------
- Time Complexity: O(N)
  Reason: Each index enters and leaves the deque at most once.
- Space Complexity: O(k)
  Reason: Deque stores at most k indices.

8. IMPORTANT TIPS, TRAPS & EDGE CASES
--------------------------------------------------------------------------------
- Store INDICES in the deque, not values, so you can easily check if an element is out of window bounds (`q.peek() <= i - k`).
