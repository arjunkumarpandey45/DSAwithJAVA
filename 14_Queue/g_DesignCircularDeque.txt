================================================================================
QUESTION: Design Circular Deque (LeetCode 641)
FILE: g_DesignCircularDeque.java
================================================================================

1. WHAT IS THIS PROBLEM ABOUT?
--------------------------------------------------------------------------------
Design a Circular Double Ended Queue with fixed capacity supporting insertFront, insertLast, deleteFront, deleteLast, getFront, getRear, isEmpty, and isFull.

2. HOW TO THINK (INTUITION)?
--------------------------------------------------------------------------------
Fixed array of size `k` with `front`, `rear`, and `size` variables:
- insertLast: `arr[rear] = val; rear = (rear + 1) % k; size++;`
- deleteFront: `front = (front + 1) % k; size--;`
- insertFront: move front backward! `front = (front - 1 + k) % k; arr[front] = val; size++;`
- deleteLast: move rear backward! `rear = (rear - 1 + k) % k; size--;`

3. STEP-BY-STEP APPROACH
--------------------------------------------------------------------------------
1. int[] arr, int front = 0, rear = 0, size = 0, cap = k;
2. insertFront(val): if (isFull()) return false; front = (front - 1 + cap) % cap; arr[front] = val; size++; return true;
3. insertLast(val): if (isFull()) return false; arr[rear] = val; rear = (rear + 1) % cap; size++; return true;
4. deleteFront(): if (isEmpty()) return false; front = (front + 1) % cap; size--; return true;
5. deleteLast(): if (isEmpty()) return false; rear = (rear - 1 + cap) % cap; size--; return true;
6. getFront(): return isEmpty() ? -1 : arr[front];
7. getRear(): return isEmpty() ? -1 : arr[(rear - 1 + cap) % cap];

4. WHY THIS WORKS?
--------------------------------------------------------------------------------
Modulo arithmetic wraps in both directions: `+ 1` moves clockwise, `- 1 + cap` moves counter-clockwise.

5. WHY NOT OTHER APPROACHES (WHY NOT THAT)?
--------------------------------------------------------------------------------
Using `size` counter eliminates complex pointer arithmetic (like reserving one empty slot) to distinguish between empty and full.

6. STEP-BY-STEP DRY RUN
--------------------------------------------------------------------------------
cap = 3, front=0, rear=0, size=0
insertLast(1) -> arr[0]=1, rear=1, size=1
insertLast(2) -> arr[1]=2, rear=2, size=2
insertFront(3) -> front=(0-1+3)%3=2, arr[2]=3, size=3 (Full!)
getRear() -> arr[(2-1+3)%3] = arr[1] = 2
getFront() -> arr[front(2)] = 3

7. COMPLEXITY ANALYSIS
--------------------------------------------------------------------------------
- Time Complexity: O(1) for all methods
  Reason: Direct indexing and arithmetic.
- Space Complexity: O(K)
  Reason: Fixed array allocation of size K.

8. IMPORTANT TIPS, TRAPS & EDGE CASES
--------------------------------------------------------------------------------
- Always add `+ cap` before modulo when subtracting 1: `(idx - 1 + cap) % cap` to prevent negative array index.
