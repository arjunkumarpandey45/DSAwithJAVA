================================================================================
QUESTION: Height of Binary Tree (By Levels vs By Edges)
FILE: a_BasicBinaryTree2.java
================================================================================

1. WHAT IS THIS PROBLEM ABOUT?
--------------------------------------------------------------------------------
Calculate the height/depth of a binary tree. Distinguishes height measured by number of nodes (levels) vs number of edges.

2. HOW TO THINK (INTUITION)?
--------------------------------------------------------------------------------
Height is the longest path from root down to a leaf:
- Height of my left subtree is `hLeft`.
- Height of my right subtree is `hRight`.
- My height is: `1 + Math.max(hLeft, hRight)` (by nodes/levels)!
- If measuring by edges, an empty tree has height -1, and a single-node tree has height 0.

3. STEP-BY-STEP APPROACH
--------------------------------------------------------------------------------
1. Height by Levels (Node count):
   - if (root == null) return 0;
   - return 1 + Math.max(heightByLevel(root.left), heightByLevel(root.right));
2. Height by Edges:
   - if (root == null) return -1;
   - return 1 + Math.max(heightByEdge(root.left), heightByEdge(root.right));

4. WHY THIS WORKS?
--------------------------------------------------------------------------------
Postorder divide-and-conquer: evaluates heights of both child subtrees before combining them at the parent.

5. WHY NOT OTHER APPROACHES (WHY NOT THAT)?
--------------------------------------------------------------------------------
Counting edges requires distinguishing between an empty tree (-1) and a single-node tree (0). Height by levels is cleaner and used by LeetCode (empty tree = 0).

6. STEP-BY-STEP DRY RUN
--------------------------------------------------------------------------------
Tree: 1 -> left: 2, right: 3 -> 2 has left: 4
Node 4: left=0, right=0 -> height = 1 + max(0, 0) = 1
Node 2: left=1, right=0 -> height = 1 + max(1, 0) = 2
Node 3: left=0, right=0 -> height = 1 + max(0, 0) = 1
Root 1: left=2, right=1 -> height = 1 + max(2, 1) = 3 (levels)!

7. COMPLEXITY ANALYSIS
--------------------------------------------------------------------------------
- Time Complexity: O(N)
  Reason: Visits every node once.
- Space Complexity: O(H)
  Reason: Call stack proportional to tree height H (O(log N) balanced, O(N) skewed).

8. IMPORTANT TIPS, TRAPS & EDGE CASES
--------------------------------------------------------------------------------
- Always check the problem definition: does "height" mean number of NODES or number of EDGES?
