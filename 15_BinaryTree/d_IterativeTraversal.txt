================================================================================
QUESTION: Iterative Preorder, Inorder, and Postorder Traversals
FILE: d_IterativeTraversal.java
================================================================================

1. WHAT IS THIS PROBLEM ABOUT?
--------------------------------------------------------------------------------
Perform Preorder, Inorder, and Postorder tree traversals iteratively using explicit stacks without recursion.

2. HOW TO THINK (INTUITION)?
--------------------------------------------------------------------------------
Iterative Preorder (Root, Left, Right):
Push root to stack. While stack not empty: pop node, print value, push RIGHT child, then push LEFT child (left is pushed last so it pops first!).

Iterative Inorder (Left, Root, Right):
Walk all the way LEFT pushing nodes onto stack. When you hit null, pop from stack, print, and move to `node.right`!

3. STEP-BY-STEP APPROACH
--------------------------------------------------------------------------------
Iterative Inorder:
1. Stack<Node> st = new Stack<>(); Node curr = root;
2. while (curr != null || !st.isEmpty()):
   - while (curr != null): st.push(curr); curr = curr.left;
   - curr = st.pop();
   - ans.add(curr.data);
   - curr = curr.right;
3. return ans;

4. WHY THIS WORKS?
--------------------------------------------------------------------------------
The explicit stack replaces the implicit JVM call stack, allowing traversal without risk of JVM StackOverflowError on deeply skewed trees.

5. WHY NOT OTHER APPROACHES (WHY NOT THAT)?
--------------------------------------------------------------------------------
Why learn iterative when recursive is shorter?
Recursion crashes on trees with depth > 10,000 in Java. Iterative implementations run safely on the heap.

6. STEP-BY-STEP DRY RUN
--------------------------------------------------------------------------------
Tree: 1 with left: 2, right: 3
Inorder: push 1, push 2 -> curr=null -> pop 2 (print 2) -> curr=2.right(null) -> pop 1 (print 1) -> curr=1.right(3) -> push 3 -> pop 3 (print 3) -> Output: 2, 1, 3

7. COMPLEXITY ANALYSIS
--------------------------------------------------------------------------------
- Time Complexity: O(N)
  Reason: Each node pushed and popped once.
- Space Complexity: O(H)
  Reason: Stack holds at most tree height H.

8. IMPORTANT TIPS, TRAPS & EDGE CASES
--------------------------------------------------------------------------------
- In Preorder, remember to push `node.right` BEFORE `node.left` so that `left` is on top of the stack and processed first.
