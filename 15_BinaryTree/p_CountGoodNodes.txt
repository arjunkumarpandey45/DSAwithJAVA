================================================================================
QUESTION: Count Good Nodes in Binary Tree (LeetCode 1448)
FILE: p_CountGoodNodes.java
================================================================================

1. WHAT IS THIS PROBLEM ABOUT?
--------------------------------------------------------------------------------
A node X in the tree is named "good" if in the path from the root to X, there are no nodes with a value greater than X. Return the number of good nodes.

2. HOW TO THINK (INTUITION)?
--------------------------------------------------------------------------------
As you traverse down from the root, keep track of `maxSoFar` on the current path.
- If `root.val >= maxSoFar`: this node is GOOD! Count = 1, update `maxSoFar = root.val`.
- If `root.val < maxSoFar`: this node is NOT good! Count = 0.
Total = `good + dfs(root.left, maxSoFar) + dfs(root.right, maxSoFar)`.

3. STEP-BY-STEP APPROACH
--------------------------------------------------------------------------------
1. goodNodes(root): return dfs(root, root.val);
2. dfs(root, max):
   - if (root == null) return 0;
   - int good = 0;
   - if (root.val >= max): good = 1; max = root.val;
   - return good + dfs(root.left, max) + dfs(root.right, max);

4. WHY THIS WORKS?
--------------------------------------------------------------------------------
A node only needs to beat the maximum value among its ancestors. Passing `maxSoFar` along the recursive call stack carries that exact invariant.

5. WHY NOT OTHER APPROACHES (WHY NOT THAT)?
--------------------------------------------------------------------------------
Checking all ancestors by walking upward requires parent pointers (O(N) extra space). Top-down DFS checks in O(1) state per call.

6. STEP-BY-STEP DRY RUN
--------------------------------------------------------------------------------
Tree: [3, 1, 4, 3, null, 1, 5]
- root 3: 3 >= 3 -> Good (1), max=3
- left 1: 1 < 3 -> Not good, max=3
  - left 3: 3 >= 3 -> Good (2), max=3
- right 4: 4 >= 3 -> Good (3), max=4
  - right 5: 5 >= 4 -> Good (4), max=5
Total good nodes = 4.

7. COMPLEXITY ANALYSIS
--------------------------------------------------------------------------------
- Time Complexity: O(N)
  Reason: Visits each node once.
- Space Complexity: O(H)
  Reason: Recursion stack.

8. IMPORTANT TIPS, TRAPS & EDGE CASES
--------------------------------------------------------------------------------
- Condition is `>=`: equal values are considered good nodes!
