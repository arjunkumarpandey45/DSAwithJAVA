================================================================================
QUESTION: Count Complete Tree Nodes in Less Than O(N) (LeetCode 222)
FILE: r_CountNodeInCBT.java
================================================================================

1. WHAT IS THIS PROBLEM ABOUT?
--------------------------------------------------------------------------------
Count the number of nodes in a COMPLETE binary tree in strictly less than O(N) time complexity.

2. HOW TO THINK (INTUITION)?
--------------------------------------------------------------------------------
A full binary tree of height `h` has exactly `2^h - 1` nodes!
Check left height (walking strictly down left pointers) and right height (strictly down right pointers):
- If `leftHeight == rightHeight`: This subtree is a PERFECT binary tree! Number of nodes is `(1 << leftHeight) - 1` without visiting internal nodes!
- If `leftHeight != rightHeight`: Not perfect, so: `1 + countNodes(root.left) + countNodes(root.right)`.

3. STEP-BY-STEP APPROACH
--------------------------------------------------------------------------------
1. if (root == null) return 0;
2. int lh = getLeftHeight(root);
3. int rh = getRightHeight(root);
4. if (lh == rh) return (1 << lh) - 1;
5. return 1 + countNodes(root.left) + countNodes(root.right);
6. getLeftHeight(node): int h = 0; while (node != null) { h++; node = node.left; } return h;

4. WHY THIS WORKS?
--------------------------------------------------------------------------------
In a complete binary tree, at least one of the two subtrees at every level is guaranteed to be a perfect binary tree and evaluated in O(log N) time using the 2^h - 1 formula.

5. WHY NOT OTHER APPROACHES (WHY NOT THAT)?
--------------------------------------------------------------------------------
Simple `1 + count(left) + count(right)` is O(N). This algorithm runs in O((log N)^2).

6. STEP-BY-STEP DRY RUN
--------------------------------------------------------------------------------
Full tree of 3 levels: lh=3, rh=3 -> (1 << 3) - 1 = 8 - 1 = 7 nodes in O(log N) operations!

7. COMPLEXITY ANALYSIS
--------------------------------------------------------------------------------
- Time Complexity: O((log N)^2)
  Reason: Tree height is log N. At each level, height computation takes O(log N). Total = (log N) * (log N).
- Space Complexity: O(log N)
  Reason: Recursion stack on balanced complete tree.

8. IMPORTANT TIPS, TRAPS & EDGE CASES
--------------------------------------------------------------------------------
- Bit shift `(1 << h) - 1` computes 2^h - 1 quickly in integer arithmetic.
