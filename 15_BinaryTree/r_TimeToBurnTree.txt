================================================================================
QUESTION: Amount of Time for Binary Tree to Be Infected / Burning Tree
FILE: r_TimeToBurnTree.java
================================================================================

1. WHAT IS THIS PROBLEM ABOUT?
--------------------------------------------------------------------------------
A fire starts at a target node in a binary tree. Every second, the fire spreads to adjacent connected nodes (left child, right child, and parent). Find the time required for the entire tree to burn.

2. HOW TO THINK (INTUITION)?
--------------------------------------------------------------------------------
Fire spreads radially 1 unit of distance per second in all directions (left, right, parent).
Total time to burn the tree = MAXIMUM distance from start node to any other node!
Step 1: Map parents using BFS.
Step 2: BFS outward from start node level-by-level until queue is empty.
Number of BFS waves = burning time!

3. STEP-BY-STEP APPROACH
--------------------------------------------------------------------------------
1. Map<TreeNode, TreeNode> parentMap; build via BFS.
2. Queue<TreeNode> q = new LinkedList<>(); q.offer(startNode);
3. Set<TreeNode> visited = new HashSet<>(); visited.add(startNode);
4. int time = -1;
5. while (!q.isEmpty()):
   - int size = q.size();
   - for i = 0 to size - 1:
     - curr = q.poll();
     - for neighbor in (curr.left, curr.right, parentMap.get(curr)):
       - if neighbor != null && !visited.contains(neighbor):
         - visited.add(neighbor); q.offer(neighbor);
   - time++;
6. Return time;

4. WHY THIS WORKS?
--------------------------------------------------------------------------------
Unweighted graph BFS naturally simulates concurrent radial expansion at 1 step per second.

5. WHY NOT OTHER APPROACHES (WHY NOT THAT)?
--------------------------------------------------------------------------------
Simulating second-by-second without graph BFS is complex. Graph conversion reduces it to standard multi-direction BFS.

6. STEP-BY-STEP DRY RUN
--------------------------------------------------------------------------------
Tree: 1 -> (2, 3), start = 2
t=0: start at 2
t=1: 2 infects parent 1 -> infected {2, 1}
t=2: 1 infects child 3 -> infected {2, 1, 3}
Total time = 2 seconds.

7. COMPLEXITY ANALYSIS
--------------------------------------------------------------------------------
- Time Complexity: O(N)
  Reason: Parent mapping O(N) + BFS O(N).
- Space Complexity: O(N)
  Reason: Queue, parent map, and visited set.

8. IMPORTANT TIPS, TRAPS & EDGE CASES
--------------------------------------------------------------------------------
- Start `time = -1` (or increment only when new nodes are actually burned) so that a tree with only 1 node returns 0 seconds.
