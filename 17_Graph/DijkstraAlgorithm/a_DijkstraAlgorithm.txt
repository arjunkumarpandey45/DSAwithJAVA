================================================================================
QUESTION: Dijkstra's Algorithm for Shortest Path
FILE: a_DijkstraAlgorithm.java
================================================================================

1. WHAT IS THIS PROBLEM ABOUT?
--------------------------------------------------------------------------------
Find the shortest distance from a single source vertex to all vertices in a weighted graph with non-negative edge weights.

2. HOW TO THINK (INTUITION)?
--------------------------------------------------------------------------------
Greedy Breadth First Search using a MIN-HEAP (PriorityQueue):
Store pairs `(dist, node)` in min-heap.
Always pick the unvisited node with the SMALLEST known distance from source.
Relax its neighbors: if `dist[node] + weight < dist[neighbor]`, update `dist[neighbor]` and push to min-heap.

3. STEP-BY-STEP APPROACH
--------------------------------------------------------------------------------
1. int[] dist = new int[V]; Arrays.fill(dist, Integer.MAX_VALUE); dist[src] = 0;
2. PriorityQueue<Pair> pq = new PriorityQueue<>((a, b) -> a.dist - b.dist);
3. pq.offer(new Pair(0, src));
4. while (!pq.isEmpty()):
   - Pair p = pq.poll(); int d = p.dist, u = p.node;
   - if (d > dist[u]) continue; // stale entry
   - for each edge (v, wt) from u:
     - if (d + wt < dist[v]): dist[v] = d + wt; pq.offer(new Pair(dist[v], v));
5. Return dist.

4. WHY THIS WORKS?
--------------------------------------------------------------------------------
Because edge weights are non-negative, the shortest distance to the node currently at the top of the min-heap cannot be improved by any other path.

5. WHY NOT OTHER APPROACHES (WHY NOT THAT)?
--------------------------------------------------------------------------------
Dijkstra FAILS on negative edge weights (infinite loop or incorrect greedy finality). Use Bellman-Ford for negative weights.

6. STEP-BY-STEP DRY RUN
--------------------------------------------------------------------------------
0 -> 1(wt 4), 0 -> 2(wt 1), 2 -> 1(wt 2)
pq = [(0, 0)], dist = [0, inf, inf]
poll (0, 0): relax 1 -> dist[1]=4; relax 2 -> dist[2]=1. pq=[(1, 2), (4, 1)]
poll (1, 2): relax 1 -> 1 + 2 = 3 < dist[1](4) -> dist[1]=3! pq=[(3, 1), (4, 1)]
poll (3, 1): finalized.
Result dist: [0, 3, 1]

7. COMPLEXITY ANALYSIS
--------------------------------------------------------------------------------
- Time Complexity: O(E log V)
  Reason: Each edge relaxed and pushed to heap in log V time.
- Space Complexity: O(V + E)
  Reason: Priority queue and distance array.

8. IMPORTANT TIPS, TRAPS & EDGE CASES
--------------------------------------------------------------------------------
- Always add `if (d > dist[u]) continue;` to skip outdated pairs in the PriorityQueue.
