================================================================================
QUESTION: Shortest Path in Directed Acyclic Graph (DAG) Using Topological Sort
FILE: e_ShortestPathDAG_DFS.java
================================================================================

1. WHAT IS THIS PROBLEM ABOUT?
--------------------------------------------------------------------------------
Find the shortest path from a source vertex to all other vertices in a Directed Acyclic Graph (DAG) with edge weights in O(V + E) time.

2. HOW TO THINK (INTUITION)?
--------------------------------------------------------------------------------
In a DAG, why use Dijkstra O(E log V) when we can do it in O(V + E)?
TOPOLOGICAL SORT gives the exact chronological dependency order!
1. Find topological sort of the graph.
2. Initialize `dist[] = INF`, `dist[src] = 0`.
3. Process vertices in TOPOLOGICAL ORDER:
   For current vertex `u`:
   Relax all outgoing edges `u -> v`: `dist[v] = min(dist[v], dist[u] + wt)`!
Because vertices are processed in topo order, when we reach vertex `v`, ALL possible paths to `v` have ALREADY been fully relaxed!

3. STEP-BY-STEP APPROACH
--------------------------------------------------------------------------------
1. Find topo sort using DFS stack (or Kahn's): Stack<Integer> st.
2. int[] dist = new int[V]; Arrays.fill(dist, (int)1e9); dist[src] = 0;
3. while (!st.isEmpty()):
   - int u = st.pop();
   - if (dist[u] != 1e9):
     - for (v, wt) in adj.get(u):
       - if (dist[u] + wt < dist[v]) dist[v] = dist[u] + wt;
4. Replace 1e9 with -1 for unreachable nodes, return dist.

4. WHY THIS WORKS?
--------------------------------------------------------------------------------
In a DAG, there are no cycles. Processing nodes in topological order is a Dynamic Programming forward pass: every sub-path is solved before it is used.

5. WHY NOT OTHER APPROACHES (WHY NOT THAT)?
--------------------------------------------------------------------------------
Dijkstra uses O(E log V) with heap overhead. Topo-relaxation runs in pure linear O(V + E) and handles negative edge weights!

6. STEP-BY-STEP DRY RUN
--------------------------------------------------------------------------------
Topo order: 0, 1, 2. src = 0, dist=[0, inf, inf]
Process 0: edges 0->1(2), 0->2(4) -> dist=[0, 2, 4]
Process 1: edge 1->2(1) -> dist[2] = min(4, 2 + 1 = 3) -> dist=[0, 2, 3]
Process 2: no outgoing edges.
Final dist: [0, 2, 3]

7. COMPLEXITY ANALYSIS
--------------------------------------------------------------------------------
- Time Complexity: O(V + E)
  Reason: Topo sort O(V + E) + single relaxation pass O(V + E).
- Space Complexity: O(V + E)
  Reason: Adjacency list, stack, and distance array.

8. IMPORTANT TIPS, TRAPS & EDGE CASES
--------------------------------------------------------------------------------
- Only relax neighbors if `dist[u] != INF`! If node `u` is unreachable from source, its outgoing edges cannot form a valid path from source.
