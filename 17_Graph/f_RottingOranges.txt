================================================================================
QUESTION: Rotting Oranges (LeetCode 994)
FILE: f_RottingOranges.java
================================================================================

1. WHAT IS THIS PROBLEM ABOUT?
--------------------------------------------------------------------------------
Every minute, any fresh orange that is 4-directionally adjacent to a rotten orange becomes rotten. Return the minimum minutes until no fresh orange remains, or -1 if impossible.

2. HOW TO THINK (INTUITION)?
--------------------------------------------------------------------------------
MULTI-SOURCE BFS:
Why Multi-Source? Because all initially rotten oranges rot their neighbors AT THE SAME TIME (concurrently)!
Step 1: Put ALL initially rotten oranges (value 2) into the queue at time 0. Count total fresh oranges.
Step 2: Run BFS level-by-level (each level = 1 minute):
Poll rotten orange, infect its 4 fresh neighbors (turn to 2), add to queue, decrement `freshCount`.
Step 3: If `freshCount == 0`, return minutes elapsed; else return -1!

3. STEP-BY-STEP APPROACH
--------------------------------------------------------------------------------
1. Queue<int[]> q = new LinkedList<>(); int fresh = 0;
2. For r = 0..m-1, c = 0..n-1:
   - if (grid[r][c] == 2) q.offer(new int[]{ r, c });
   - if (grid[r][c] == 1) fresh++;
3. if (fresh == 0) return 0;
4. int minutes = -1;
5. while (!q.isEmpty()):
   - int size = q.size();
   - for i = 0 to size - 1:
     - int[] curr = q.poll();
     - for 4 directions (nr, nc):
       - if (valid && grid[nr][nc] == 1):
         - grid[nr][nc] = 2; fresh--; q.offer(new int[]{ nr, nc });
   - minutes++;
6. Return fresh == 0 ? minutes : -1;

4. WHY THIS WORKS?
--------------------------------------------------------------------------------
BFS explores in unit-time concentric rings. Running BFS from all rotten sources concurrently correctly mirrors real-world simultaneous viral infection.

5. WHY NOT OTHER APPROACHES (WHY NOT THAT)?
--------------------------------------------------------------------------------
Why not DFS?
DFS explores one branch deeply, falsely assuming one orange rots the whole grid while other rotten oranges sit idle. Rotting is parallel, so BFS is mandatory.

6. STEP-BY-STEP DRY RUN
--------------------------------------------------------------------------------
grid = [
  [2, 1, 1],
  [1, 1, 0],
  [0, 1, 1]
]
Initial rotten: (0,0). Fresh = 6.
- Min 1: (0,0) rots (0,1) and (1,0) -> fresh=4
- Min 2: rots (0,2) and (1,1) -> fresh=2
- Min 3: rots (2,1) -> fresh=1
- Min 4: rots (2,2) -> fresh=0!
Output: 4 minutes.

7. COMPLEXITY ANALYSIS
--------------------------------------------------------------------------------
- Time Complexity: O(M * N)
  Reason: Each cell processed in queue at most once.
- Space Complexity: O(M * N)
  Reason: Queue storing coordinates.

8. IMPORTANT TIPS, TRAPS & EDGE CASES
--------------------------------------------------------------------------------
- If `fresh == 0` at the very start, return 0 minutes immediately!
