QUESTION: Is Graph Bipartite? (LeetCode 785)
FILE: l_BipartiteGraph.java
================================================================================

1. WHAT IS THIS PROBLEM ABOUT?
--------------------------------------------------------------------------------
A graph is bipartite if we can split its nodes into two sets A and B such that every edge connects a node in A to a node in B (no two adjacent nodes share the same color).

2. HOW TO THINK (INTUITION)?
--------------------------------------------------------------------------------
2-COLORING PROBLEM:
Can you color the graph using only TWO colors (say Color 0 and Color 1) such that no neighbor has the same color?
THEOREM: A graph is bipartite IF AND ONLY IF it has NO ODD-LENGTH CYCLES!
- Even cycle (4 nodes): 0 -> 1 -> 0 -> 1 -> 0 (Valid 2-colorable!)
- Odd cycle (3 nodes): 0 -> 1 -> 0 -> ??? (Needs 3rd color! NOT bipartite!)
Use BFS / DFS with a `color[]` array initialized to -1.

3. STEP-BY-STEP APPROACH
--------------------------------------------------------------------------------
1. int[] color = new int[V]; Arrays.fill(color, -1);
2. For i = 0 to V - 1:
   - if (color[i] == -1):
     - if (!bfsCheck(i, graph, color)) return false;
3. bfsCheck(start, graph, color):
   - Queue<Integer> q = new LinkedList<>(); q.offer(start); color[start] = 0;
   - while (!q.isEmpty()):
     - int node = q.poll();
     - for neighbor in graph[node]:
       - if (color[neighbor] == -1):
         - color[neighbor] = 1 - color[node]; // opposite color
         - q.offer(neighbor);
       - else if (color[neighbor] == color[node]):
         - return false; // same color conflict!
   - return true;
4. Return true.

4. WHY THIS WORKS?
--------------------------------------------------------------------------------
Assigning `1 - color[node]` forces alternating colors. If a node ever encounters an already-colored neighbor with the same color, a conflict exists, proving an odd cycle.

5. WHY NOT OTHER APPROACHES (WHY NOT THAT)?
--------------------------------------------------------------------------------
Checking cycle lengths explicitly requires complex cycle enumeration. 2-coloring detects odd cycles in a single linear pass.

6. STEP-BY-STEP DRY RUN
--------------------------------------------------------------------------------
Triangle: 0 - 1, 1 - 2, 2 - 0
color[0] = 0
- neighbor 1: color[1] = 1
- neighbor 2: color[2] = 1
- when checking edge between 1 and 2: color[1] == 1 and color[2] == 1 (SAME COLOR!) -> CONFLICT! Return false!

7. COMPLEXITY ANALYSIS
--------------------------------------------------------------------------------
- Time Complexity: O(V + 2E)
  Reason: Standard BFS/DFS traversal.
- Space Complexity: O(V)
  Reason: Color array and queue.

8. IMPORTANT TIPS, TRAPS & EDGE CASES
--------------------------------------------------------------------------------
- Toggle color using `1 - currentColor` (0 becomes 1, 1 becomes 0).
